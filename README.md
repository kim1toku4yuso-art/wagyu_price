# Git Lesson

##リモートリポジトリとローカルリポジトリとはそれぞれ何でしょうか？

リモートリポジトリとは、GitHubなどのネットワーク上にある「共有・バックアップ用の保管場所」である。

ローカルリポジトリとは、自分のパソコン内にある「自分専用の作業・保管場所」である。




##プッシュとマージの違いは何でしょうか？

プッシュは、ローカルの変更をリモートに送信して共有することで
マージは、別々の作業履歴(ブランチ)を一つに合流させることである。

よって、「場所を移す」か「履歴を合体させる」かという違いがある。



##コミットとプッシュの違い

コミットは、自分のPC(ローカルリポジトリ)に変更履歴を保存することである。

プッシュはその変更した履歴をネット上(リモートリポジトリ)へ送信することである。

よって、自分のPC内で完結する記録か外部への共有かという違いがある。



##コミットのメッセージはどのように書いてあげるのが最適でしょうか？

メッセージの先頭に「変更の種類」を表すラベル(プレフィックス)を付けると、履歴の一覧を見ただけでどんな作業かすぐに判別することができる。

一行目は短く具体的に、「どうやったか」ではなく「何をしたか、なぜしたか」を書く、一つのコミットに複数の目的を混ぜないという点に気を付ける。



##ローカルでマージするフローと、プルリクエストでマージするフローの違いは何でしょうか？

ローカルでのマージは、自分のPC内で完結する即時の統合作業であり、プルリクエストでのマージはGitHubなどのWeb上で他の人に確認してもらってから統合するチーム向けの仕組みである。

よって、他の人のチェックが入るかどうかと、どこで操作するかという点に違いがある。



##コンフリクトを起してしまった場合、どう対処すべきですか？

1.コンフリクトが起きているファイルを確認する

コマンドの場合、git statusを打つと、赤文字で該当ファイルが表示される。
VS Codeなどのエディタを使っている場合は、左側のソース管理タブに「!」マーク付きで一覧が出る。

2.該当ファイルを開き、記号(マーカー)を探す

<<<<<<< HEADから=======までが自分の変更
=======から>>>>>>> ブランチ名までが相手の変更である。

3.残したいコードに書き換える(記号も消す)

三通りの方法がある。

一つ目は、マージされた変更内容を取り込む。
二つ目は、後にマージしようとしている変更内容を取り込む。
三つめは、どちらの変更内容も取り込む。

どれを選択するかに関しては、状況によって異なる。

4.修正を保存してコミットする
